## Windows 기존 변경 보존

아직 커밋하지 않은 공식 업데이트를 강제 삭제하거나 전체 ZIP으로 덮어쓰지 않는다. 먼저 `git status --short`, `git log -1 --oneline`으로 실제 상태를 확인한다. 로컬 커밋이 있으면 해당 커밋을 유지한다. 미커밋이면 별도 로컬 브랜치에 업데이트만 검토하여 저장한 뒤 최종 main을 다른 작업 트리로 받을 수 있다. stash pop/강제 reset 없이 기존 폴더를 보존하는 방식이 우선이다. 실제 상태를 받기 전 일괄 복구 명령은 실행하지 않는다.

## 담당자 안내 도착 후

1. 제공 파일·설치 절차·대상 버전 확인. 계정/AI 승인과 앱 실행 환경 승인은 별개.
2. 안내에 따라 runtime 및 host 설치. 파일 존재만으로 승인 성공이라고 하지 않음.
3. 최종 main이 깨끗한지, 아이콘 규격·경로, 새 출력 폴더 확인.
4. 공식 package-app --finish-materials 실행. 같은 명령의 네 파일과 manifest·INSTALL.md 보관.
5. INSTALL.md로 새 경로 설치 → 승인 host 바로가기 실행 → 학생 기능 확인.
6. 실제 payload로 Inno 사용자 단위 설치·제거를 구성하고 검증. 지금 만든 setup.exe는 없음.
7. 실제 캡처, source.git.head, 실행 환경/한계와 시연 결과를 기록하고 안내된 제출 경로 사용.
