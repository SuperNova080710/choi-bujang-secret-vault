# GitHub 서비스 조회 준비

## 현재 상태

2026-10-27, 공식 시작 틀 0.2.19 소스를 기준으로 조사했습니다. GitHub 연결 전 화면만 구현했으며 실제 서비스 연동은 미구현입니다. 예시 수치, 0원, 안전 판정을 표시하지 않습니다.

## 확인 근거

| 소스 | 확인 내용 |
|---|---|
| `on-client/public/app.js`의 `STUDENT_GET_PATHS` | `/api/me`, `/api/apps`, `/api/events`, `/api/devices`, `/api/sessions`, `/api/vulnerabilities`, `/api/pc/status`만 허용 |
| `on-client/src/server.mjs` | GitHub 전용 조회 경로 없음 |
| `on-client/docs/PC_SAAS_REFERENCE.md` | 담당자가 허용한 연결 방법만 사용하며 새 주소나 직접 fetch로 우회하지 않음 |
| `on-client/examples/pc-saas/README.md` | 서비스 값은 예시이며 인증·외부 요청 구현이 아님 |

기존 `/api/apps`를 GitHub 저장소 API로 해석하거나 경로를 임의로 추가하지 않습니다. ChatGPT의 GitHub 연결은 개발 작업용이며, 설치형 앱의 사용자 인증으로 이전할 수 없습니다.

## 담당자에게 확인할 계약

1. 학생 API에서 GitHub 읽기 전용 조회를 지원하는 버전과 정확한 경로가 있는지.
2. 인증정보를 서버에 설정하는 공식 방법, 최소 권한, 해제 방법.
3. 반환 스키마, 출처·측정 시각, 권한 부족·부분 결과·요청 제한·실패의 구분.
4. 저장소 변경·이슈·자동 검사 중 지원 항목, 사용량·비용 API 지원 여부와 계정 종류별 제한.

토큰 값 자체를 요청하거나 문서·브라우저 저장소에 넣지 않습니다. 응답 계약이 확인되면 별도 브랜치에서 수동 조회와 오류·취소·부분 결과 처리를 구현합니다. 지원하지 않는 비용/보안 항목은 계속 확인 불가로 남깁니다.

## 확인 방법

`on-client`에서 `npm.cmd run demo` 실행 후 보호 현황의 GitHub 서비스 카드를 확인합니다.

- 정상: 연결 전·확인 불가, 미조회, 다음 행동이 표시됨.
- 허용하지 않는 결과: 조회하지 않았는데 0원·정상·안전으로 표시하거나 토큰 입력창을 제공함.
- PC의 다시 조회 버튼은 기존 PC 조회만 수행함.

## 제출 및 배포와의 구분

사용자가 전달한 변경 안내에 따르면 과제는 저장소 URL과 커밋 번호로 제출합니다. 최신 안내의 제출 위치는 과제 화면의 마무리 자료 제출 창입니다. 실제 접수·판정은 아직 수행하지 않았습니다. 외부 SaaS 실연동은 선택 사항이며 기다릴 필요가 없습니다. package-app 대기를 과제 제출의 필수 조건으로 해석하지 않습니다.

Microsoft Store 게시·설치형 실행·재배포 권한은 이번 작업에서 검증하지 않았습니다. 소개 자료에는 현재 확인된 수동 PC 조회, 최대 30회 메모리 기록, 비교·필터·삭제만 기능으로 기재할 수 있습니다. GitHub 실연동, 보안 인증, 자동 위협 차단을 구현 기능으로 광고하지 않습니다.
