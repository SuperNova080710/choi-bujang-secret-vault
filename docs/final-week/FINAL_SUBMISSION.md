## 재실행과 시연 순서

기존 계정·AI 승인이 있는 Windows 프로젝트의 `on-client` 폴더에서 실행합니다. 현재 소스는 0.2.19입니다. 과제 상단의 0.2.21 안내와 별개로 최종 제출 절차에서 업데이트 도구를 실행하지 말라고 명시하므로 이번 제출 준비에서는 제공 코드를 교체하지 않았습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

터미널에 표시된 로컬 주소(기본 `http://127.0.0.1:5189`)를 열고 **보호 현황 → 학생 상태·알림 표시 → 내 PC 조회 타임라인**으로 이동합니다.

1. **상태 보기:** 다시 조회 → 읽힌 항목과 확인 불가 항목, 시각·출처를 설명합니다. SDP 연결 없음은 PC 실측과 별개입니다.
2. **변화 보기:** 출처를 펼치고 다시 조회 → 직전 변화와 관찰 요약을 설명합니다. 값의 변화·경고 건수는 침해 판정이 아닙니다.
3. **기록 관리:** 기록 필터 변경 → 최신 카드와 열린 출처 유지 확인 → 기록 지우기 → 재조회. 삭제 뒤 1회부터 다시 기록됩니다.

정상 결과는 읽은 수치와 근거가 표시되는 것입니다. 허용하지 않는 결과는 결측을 0·안전으로 바꾸거나, 취소·삭제 후 늦은 응답으로 기록을 되살리거나, 미연결을 성공으로 표시하는 것입니다. `npm start`는 공식 계정 연결 준비를 대체하지 않습니다. `npm run demo`의 보안 기록은 예제이며 실제 운영 기록이라고 소개하지 않습니다.

OSV를 같은 승인 범위로 다시 조회할 때는 저장소 루트의 잠금 파일과 설치 파일이 필요합니다. 이미 설치된 사용자 환경은 재설치할 필요가 없습니다. 같은 PowerShell의 `on-client`에서 다음 설정 후 실행합니다.

```powershell
$env:ON_PROJECT_DIRECTORY = (Resolve-Path ..).Path
$env:ON_APPROVED_PUBLIC_PACKAGES = '["jose"]'
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

「설치 패키지 조회」를 누르면 승인한 이름과 설치 버전이 OSV로 전송됩니다. 당시 조회 결과는 아래와 같고, 이후 재조회 결과가 같다고 보장하지 않습니다.

## 남은 한계와 도움받은 부분

- SDP: 최신 안내에 따르면 이번 과정은 학생에게 개인 인증서를 발급하지 않습니다. `ENGINE_NOT_CONNECTED`는 미설정 상태이며 제출을 기다릴 이유가 아닙니다. 실제 서버 연결·세션 회수·사건 설명 생성·운영 데이터 복원은 미검증입니다.
- 기록은 메모리 최대 30회이며 새로고침·종료 시 지워집니다. 영구 보관·추세 예측 기능은 없습니다.
- 이벤트는 System/Application 최근 24시간 최대 5,000건 합산이며 일부 집계 한계가 있습니다. 네트워크 값은 구성 수이지 실시간 링크 상태가 아닙니다.
- 타인 첫 사용, 전체 키보드/배율 실기, 최종 SHA의 새 Windows 폴더 재현, 설치·제거·스토어 검증은 미실시입니다. 기존 승인 설정을 새 폴더로 복사하지 않습니다.
- GitHub 서비스 카드에는 연결 전 안내만 있습니다. 외부 SaaS 유료 사용량·비용 조회나 새 결제를 구현/실행하지 않았습니다.
- 사용자는 범위 선택, PR 검토·병합, Windows 실행·조작 및 OSV 결과 확인을 했습니다. AI는 코드 구현·테스트·문서 정리와 오류 분석을 도왔고 공식 실행·수집·승인 기능은 제공 시작 틀을 사용합니다. 확인되지 않은 동료 피드백·강사 관찰·개인별 직접 작성 비율은 만들지 않습니다.

수료 뒤 독립 실행·보안 도우미 키트는 별도 선택 작업입니다. 제출 이후 공식 도구의 안내에 따라 프로젝트 밖에서 준비하며 현재 제출 완료와 혼동하지 않습니다.
