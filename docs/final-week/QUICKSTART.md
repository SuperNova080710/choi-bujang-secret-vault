# 처음 실행 — 0.2.19 공식 PC 조회 연결

Windows Node.js 24 계열. 제공 지정값 24.19.0, 사용자 기존 확인값 24.22.1.
저장소의 `on-client`에서 실행하며 외부 npm 설치는 필요 없습니다.

## 계정 연결과 함께 실행

다른 서버를 해당 터미널의 Ctrl+C로 종료한 뒤:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

터미널의 주소(기본 http://127.0.0.1:5189)를 열고 새로고침합니다.
보호 현황 → 학생 상태·알림 표시 → 내 PC 조회 타임라인 → 다시 조회.
화면만 열면 자동으로 조회하지 않습니다. 계정·AI·SDP 상태는 PC 실측과 별개입니다.

## 계정 승인 없이 데모 기록으로 확인

```powershell
npm.cmd run demo
```

이제 학생 개발용 `start-pc.mjs`가 필수는 아닙니다. 공식 화면이 제공하는 `api.get('/api/pc/status')`를 학생 타임라인이 사용합니다. PC는 실제 서버가 실행되는 컴퓨터의 값이고, 보안 기록은 데모 자료입니다.

## 확인 순서

1. SDP 미설정이면 보안 기록 조회가 실패할 수 있습니다. 계정·AI 연결 및 PC 실측과 구분합니다. 데모 보안 기록은 실제 기록이 아닙니다.
2. PC 타임라인에서 다시 조회 → CPU·메모리·앱 위치 디스크와 출처·시각 확인.
3. 두 번 조회 → 직전 CPU·메모리 %p, 디스크 여유 GiB 변화 확인.
4. 네트워크 구성·방화벽·System/Application 합산 이벤트와 조회 한계 확인.
5. 기록 필터·기록 지우기, Tab/Enter 조작을 확인합니다. 최대 30회이며 페이지를 닫으면 사라집니다.

## 0.2.19에서 달라진 값의 의미

| 항목 | 공식 조회 의미 |
|---|---|
| CPU | 200ms 구간 사용률 |
| 메모리 | 전체−여유, GiB·비율 |
| 디스크 | 현재 앱 위치 볼륨의 사용 가능 공간. 시스템 드라이브라고 단정하지 않음 |
| 네트워크 | 비내부 인터페이스·IPv4 구성 수. 링크 Up 수 아님 |
| 이벤트 | System·Application 합산, 최근 24시간 최신 최대 5,000건. 로그별 수치로 쪼개지 않음 |
| OS | 공식 응답에 없어 추정하지 않음 |

공식 화면은 임의 학생 CSS 경로를 제공하지 않습니다. 학생 타임라인은 전역 제공 grid-2/card/row/records/event 클래스와 appearance 색·배치를 사용합니다. 데스크톱 2열·좁은 화면 1열이며, 기존 전용 CSS의 3열·점 장식과 동일하지 않습니다. #pc-status 안에서만 동작하는 pc-metrics 클래스에 의존하지 않습니다. 기존 `pc-view.css`는 구형 개발 진입점용 자료로 남으며 설치형 디자인 근거로 쓰지 않습니다.

## 오류

- npm.ps1 차단: `npm.cmd` 사용.
- 포트 사용 중: 기존 서버 창에서 Ctrl+C로 종료.
- PC 지원 없음: 시작 틀 0.2.19와 새 학생 코드를 같은 버전으로 받았는지 확인.
- 일부 항목 확인 불가: 해당 이유를 기록. 권한 상승·보안 설정 변경으로 성공을 만들지 않음.
- 취소: 학생 화면은 늦은 결과를 버림. 공식 API 내부의 진행 중 요청은 제공 제한 시간까지 남을 수 있음.
- ENGINE_NOT_CONNECTED: SDP 미연결이며 PC 조회 실패와 다름.

설치된 앱은 이 개발 명령이 아니라 공식 INSTALL.md와 승인 host 바로가기를 사용합니다. 실제 설치형 검증은 아직 미실시입니다.
