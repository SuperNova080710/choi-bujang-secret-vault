# 최부장님 PC 조회 — 처음 실행하는 분

## 준비

- Windows 일반 사용자 계정, Node.js 24 계열. 개발 검증은 24.22.1, 제공 시작 틀 지정값은 24.19.0이다.
- 이 기능이 포함된 같은 버전의 저장소를 받는다. 기존 폴더는 그대로 보관한다.
- 저장소 안의 `on-client` 폴더에서 터미널을 연다. 외부 npm 의존성 설치는 필요 없다.
- 다른 앱 서버가 5189 포트를 사용 중이면 그 서버 창에서 Ctrl+C로 종료한다.

## 실행

Windows PowerShell / Ubuntu 터미널 모두 `on-client`에서:

```text
node student/start-pc.mjs --demo
```

브라우저에서 http://127.0.0.1:5189 를 연다. 보호 현황의 **학생 상태·알림 표시 → 내 PC 조회 타임라인 → 다시 조회**를 누른다. 최대 약 16초까지 기다릴 수 있다. 화면을 여는 것만으로 PC 정보를 조회하지 않는다.

- PC 값: **이 서버가 실행되는 PC의 실측**이다. Ubuntu에서 켜면 Ubuntu CPU·메모리이며 Windows 항목은 확인 불가다.
- 기존 보안 기록: `--demo`에서는 **예제**다. 실제 SDP 연결이나 공격 탐지 성공이 아니다.
- 전체 7항목이 다 나오지 않아도 이유를 확인한다. 읽기 실패는 0이나 정상으로 바꾸지 않는다.
- 다시 조회하면 이전 조회와 CPU·메모리 비율(%p), 시스템 디스크 여유(GiB)를 비교한다. 기록은 최근 30회까지만 보관하며 페이지를 닫으면 사라진다.

화면 조작:

1. 보안 기록 메뉴에서 종류·앱·접속 상태 필터와 상세를 확인한다.
2. 보호 현황의 PC 패널에서 다시 조회한다. CPU·메모리·디스크의 출처와 시각을 펼쳐 본다.
3. 네트워크·방화벽·Windows 경고·오류를 확인한다. 이벤트 집계 기간과 10,000건 제한 여부도 확인한다.
4. 조회 기록 필터로 확인 불가만 보거나, 조회 기록 지우기로 메모리 기록을 비운다.
5. 종료는 터미널에서 Ctrl+C다.

## 막혔을 때

| 증상 | 다음 행동 |
|---|---|
| `node`를 찾지 못함 | Node 설치와 터미널 재실행 확인 |
| `PORT_IN_USE` | 기존 서버 터미널을 Ctrl+C로 종료한 뒤 다시 실행 |
| `npm.ps1` 실행 차단 | 기존 npm 명령이 필요할 때는 `npm.cmd` 사용. 위 학생 실행은 node 직접 실행 |
| PC 조회 미지원 | `npm start`/공식 실행 경로에는 학생 PC API가 없음. 서버를 끄고 위 학생 명령으로 실행 |
| Windows 항목 확인 불가 | 일반 권한·명령 제공 여부·조회 제한 시간 확인. 관리자 권한으로 전환하거나 보안 설정을 끄지 않음 |
| 취소 직후 다시 조회가 진행 중이라고 나옴 | 이미 시작된 서버 읽기가 끝날 때까지 잠시 기다린 뒤 수동 재조회 |
| 503 / ENGINE_NOT_CONNECTED | 실제 SDP 미연결. PC 조회와 별개이며 데모 자료를 실연결로 해석하지 않음 |

## 실제 계정 연결과 설치형 앱

이 진입점은 PC 기능 개발·검증용이며 실제 계정 연결 설정을 복제하지 않는다. 기존 계정 연결은 제공 `tools/start-alekov.ps1` 안내를 따른다. 제공 실행 환경이 학생 PC API를 지원하는지는 아직 확인되지 않았다. 개발 화면 성공만으로 설치형 앱까지 완성됐다고 기록하지 않는다.

처음 사용한 사람의 확인은 [LOCAL_ACCEPTANCE.md](LOCAL_ACCEPTANCE.md)에 기록한다.
