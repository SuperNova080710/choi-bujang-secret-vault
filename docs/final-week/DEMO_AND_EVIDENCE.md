# 7일차 시연·검증 근거 인수인계

## 현재 결과

1일차의 기존 Windows 데모 필터·상세와 핵심 기능 선정은 사용자 확인으로 완료했다(#129, #131). 이후 학생 PC 기능은 개발 코드·자동 검증까지 준비했으며 사용자 Windows 실측, 동료 사용, 설치형 검증과 제출은 아직 하지 않았다. 과제 통과·실제 운영 연결·제품 전체 완료라고 보고하지 않는다.

## 시연 순서 (실제 시연 전 준비안)

1. **출처 설명:** 학생 개발 진입점으로 실행한 화면임을 말한다. `--demo`의 보안 기록은 예제이고 PC 값은 서버 실행 PC 실측임을 구분한다.
2. **기록 조회:** 보안 기록 메뉴의 종류·앱·접속 상태를 바꿔 보고 상세 근거를 연다. 예제 기록을 새 공격 탐지라고 설명하지 않는다.
3. **PC 상태:** 보호 현황의 학생 PC 패널에서 다시 조회를 누른다. CPU·메모리·시스템 디스크의 단위·측정 시각·출처를 보여 준다. 한 번 더 조회하여 직전 변화(%p/GiB)를 확인한다.
4. **연결·설정·이벤트:** Windows에서 네트워크 링크 수, 세 방화벽 프로필 설정, System/Application 경고·오류를 보여 준다. 이벤트는 24시간/최대 10,000건 집계이며 침해 판정이 아니라고 설명한다.
5. **오류·한계:** 확인 불가 필터, 조회 취소, 기록 삭제와 키보드 포커스를 보여 준다. 지원되지 않는 항목을 숨기지 않는다.
6. **설치형 시연:** 공식 포장과 승인 host 연결을 검증한 뒤에만 추가한다. 현재는 미실시다.

## 실행한 자동 검사

Node v24.22.1 Linux 기준. Windows PowerShell의 결과는 모의 자료로 검사했으며 실제 Windows 명령 실행은 하지 않았다.

```text
node --test test/pc-collector.test.mjs test/pc-server.test.mjs test/pc-view.test.mjs test/final-week-preflight.test.mjs test/stage18-explanation-lifecycle.test.mjs test/stage18-explanation.test.mjs test/stage19-action.test.mjs test/stage20-vulnerabilities.test.mjs
```

- 기존 18~20단계 회귀 38개
- 수집기·HTTP 경계 9개
- PC DOM 상태·취소·필터·시간 초과·복구 6개
- 포장 사전 점검 4개
- 합계 57개 통과, 실패 0.
- 개발 환경 Linux의 실제 CPU·메모리 수집과 Windows 항목 WINDOWS_ONLY 응답 확인. 앱·학생 모듈·CSS·데모 기록 HTTP 200 확인. 이 측정은 사용자 Windows PC 결과가 아니다.

모의 DOM은 실제 브라우저 레이아웃·스크린리더 검증을 대신하지 않는다. `test/pc-browser.check.mjs`는 Playwright와 Chromium이 준비된 개발 환경에서 실행할 추가 검사다. 환경에 Chromium이 없었고 다운로드가 ZIP 오류로 실패해 브라우저 검증은 미실시다. 별도 Playwright 설치 경로를 `PLAYWRIGHT_MODULE`로 지정할 수 있고 `PC_QA_DIR`을 지정하면 그 폴더에 스크린샷을 저장한다. 앱 실행 자체에는 Playwright가 필요 없다.

## 실제 근거 기록 원칙

- 소스 커밋, OS·Node 버전, 실제 실행 명령·시각, 결과·한계를 함께 기록한다.
- Windows 값·계정 연결·설치 성공·동료 반응·캡처는 만들어 넣지 않는다.
- 실측 화면 1장 또는 실제 운영 안내에 맞는 최대 6장을 준비한다. 계정·개인 경로·주소·키는 가린다.
- 해시·패키지 경로는 최종 생성 결과에서 읽는다. 개발용 소스와 다른 버전의 포장물을 섞지 않는다.
- `LOCAL_ACCEPTANCE.md` 빈칸을 사용자가 실제 확인한 뒤 채운다.

## 남은 한계

1. 학생 진입점은 개발·검증용이다. 공식 실행 도구의 native 로그인·SDP 자격을 복제하지 않으며 승인 설치형 host에 학생 API를 연결하는 계약은 미확인이다.
2. Windows 수집은 일반 권한·정책·명령 제공 여부에 따라 확인 불가가 될 수 있다. 기본 Windows 설치 경로가 아닌 경우 PowerShell 경로 확인이 필요하다.
3. 네트워크는 어댑터 링크 수만 표시한다. IP·DNS·게이트웨이·MAC·인터넷 도달 여부를 수집하거나 판정하지 않는다.
4. 메모리는 total−free 방식이며 작업 관리자와 집계 정의가 다를 수 있다. CPU도 측정 시점·구간이 다르면 값이 다르다.
5. 방화벽은 세 프로필 설정이고 현재 적용 프로필·실제 차단 효과를 검증하지 않는다. 이벤트는 Level 2/3에 한정한다.
6. 기록은 브라우저 메모리 최대 30회이며 장기간 모니터링·자동 경고·자동 조치 기능은 없다. 새로고침하면 사라진다.
7. `package-app` 부재로 공식 패키지와 setup.exe를 만들지 않았다. 설치 파일이 생성됐다는 주장이나 최종 접수 완료 기록은 없다.
